## 11.3-1 自主管理 RS422 改为 1ms 轮询接收

对应手册：T1（1.1 / 1.2 / 1.3 / 1.4 / 1.5）

### 测什么

接收链路由"中断逐帧接收"改为"1ms 定时轮询接收"后，验证：收帧不丢、异常帧不卡死、出错后能自动恢复。

### 基准指令

统一使用**心跳指令 0x001D**（无副作用、每条必有应答）：

- 构造：`ycyk_422.send_heart()`；
- 硬判据：422 口收到 ACK 帧，IRCode = `0x001F`；
- 辅助判据（可选）：debug 口打印 `422 Heart`（需按 `U` 打开 g_u8UartEthPrintFlag，`U` 有回显）。

### 正常收帧

| 项 | 动作 | 判据 |
|---|---|---|
| 单条 | 发 1 条心跳 | 300ms 内收到 ACK |
| 连发 | 连发 100 条，间隔 100ms | ACK 计数 = 100；无校验错/长度错打印 |
| SC 通道 | 自造合法帧：`1A CF` + APID(`01 D0`) + 计数 + 长度 + 指令码 + 无数据域 + 校验和（现算）；发送前按 `+` 打开 u8_ka_print_sw | debug 口出现该帧原始字节的转发打印（Fdd_PrintArray），不看 CPU 响应 |

> 手册 1.5 空闲 30 分钟复测取消，不专门执行。

### 错误帧注入（核心，每种循环 3 次）

| 场景 | 发送字节（16 进制） | 判据（包含匹配） |
|---|---|---|
| ① 帧头 1 错 | `00` | `开头不是0XEB` |
| ② 帧头 2 错 | `EB 00` | `开头2不是0X90` |
| ③ 长度超限 | `EB 90 01 80 00 00 0F FF` | `frame len overflow` |
| ④ 校验和错 | `EB 90 01 80 00 00 00 04 00 00 00 00 00 00 00` | `receivedChecksum :0x0 ---calculatedChecksum: 0xff7a` |
| ⑤ 截断帧 | `EB 90 01 80 00 00 00 04 00 00`（10 字节后停） | 静默 1s 无打印；随后连发 3 条心跳，允许前 1~2 条被吞，断言最终恢复 |
| ⑥ 粘连帧 | 2 条心跳无间隔连发 | 收到 2 个 ACK |
| ⑦ 垃圾流 | `EB 90 00 00 00 00 00 00 00 00 00` | 校验错打印；补发心跳恢复 |
| ⑧ 纯噪声 | `55` × 10 | `开头不是0XEB` 出现 ≥10 次 |
| ⑨ SC 帧头 1 错 | `00 CF` | `开头不是0X1A` |
| ⑩ SC APID 错 | `1A CF 00 00` | `APID错误--0x0` |
| ⑪ SC 长度超限 | `1A CF 01 D0 00 00 02 00` | `frame len overflow--0x200` |

### 失败处理与通用判据

- 每种错误帧发完后补 1 条心跳，必须恢复 ACK；
- 全程 debug 口不出现上电 banner（出现即判"意外重启/卡死"失败）；
- 错误帧发送后固定处理窗口 300ms 再发下一条，避免字节粘连；
- SC 用例前幂等按 `a` 确保帧模式（`a` 无回显，重复按无副作用）。

### 实现备注

- 打印开关：`+`/`_` 控制 u8_ka_print_sw（SC 原始帧打印，无回显）；`U`/`E` 控制 g_u8UartEthPrintFlag（心跳打印，有回显）。
- 重启检测：debug 口出现上电 banner → 判失败，并自动补发 `Z`。
- 手册 6.3 规定 3.00 轮不执行错误帧全套；自动化同样只在 3.01 轮执行错误帧，3.00 轮只跑正常收帧。

### 限制

- SC 通道判据只验证到"BMU 收到并转发打印"，不含 CPU 侧执行结果。

## 11.3-2 遥测上报 JTAG 互助返回值

对应手册：2.4.1 / 2.4.2

### 测什么

0x9A13 互助指令执行后，返回值通过慢遥字段 u8JtagHelpRet 上报。验证正确执行（0x00）、三种错误分支（0xFE / 0xFD / 0xFC）以及错误后恢复正常。

正确分支会真实执行一次"主 BMU 给备 BMU 做 FPGA JTAG 升级"，全程约 6~7 分钟。该用例需要同时接**主、备两个 debug 串口**（观察点见下节）。

### 帧结构与测试数据

完整帧 = `9A 13` + 参数(3) + 校验和(1)；校验和 = 全部字节累加取低 8 位。

| 分支 | 完整帧（16 进制） | 预期返回值 | 同步打印 |
|---|---|---|---|
| 正确（主 BMU 执行，给备 BMU 升级方向） | `9A 13 FB 16 0E CC` | 0x00 | `CAN JTAG Help: dp_top time` |
| 错误① 长度不对（仅 2 字节参数） | `9A 13 FB 16 BE` | 0xFE | `CAN JTAG Help: Data Length` |
| 错误② 第 1 参数非 0xFB | `9A 13 00 16 0E D1` | 0xFD | `CAN JTAG Help: ARG[0]` |
| 错误③ 槽位参数不对 | `9A 13 FB 1E 06 CC` | 0xFC | `CAN JTAG Help: Slot` |

### 正常分支时序与双串口观察（重要）

正确分支会真实升级备 BMU 的 FPGA，这 6~7 分钟内主、备 BMU 都处于死循环状态：

| 阶段 | 主 BMU 串口 | 备 BMU 串口 |
|---|---|---|
| 执行中（约 6~7 分钟） | 持续打印 dp_top 进度：`Identifying device...`、`Looking for M2S/M2GL device...`、`Erasing FPGA Array...`、`Programming FPGA Array...`、`Verifying FPGA Array...`、`Progress: N %` | 无输出（卡死状态） |
| 执行结束 | `CAN JTAG Help: dp_top time (...)`，互助完成 | 重新出现初始化/上电打印，说明升级完成 |

- 互助期间主 BMU 主循环被 dp_top 占用，不处理 CAN 请求，**不要轮询慢遥**（无响应，等结束再读）；
- 等待窗口按 ≥8 分钟设置（6~7 分钟典型值 + 余量）；
- 备机在互助结束后重新初始化属预期结果，不作为"意外重启"判失败。

### 怎么判

- 遥测（主判据）：循环发慢遥请求 `00 AA 51 FB` → 收 28 帧；读 slowFrame[27]（第 28 帧）data[2] 的 slot 标记，**等到标记 = 2 的那次上报**，取 slowFrame[27] data[1] 即 u8JtagHelpRet（自定义数据按 4 个 slot 轮转，只有 slot=2 含该字段）；
- 同步方式：正确执行等 `CAN JTAG Help: dp_top time` 打印（约 6~7 分钟后出现）且备机重新初始化后再读慢遥；错误分支以对应打印为同步点，不涉及升级；
- 初始检查：用例开始先凑一次 slot=2 上报读 u8JtagHelpRet；上电后未跑过互助时为 0xFF，跑过则为上次执行结果（记录即可，不硬断 0xFF）；
- 恢复验证：错误分支后发一条正确指令，慢遥恢复 0x00。

### 执行顺序

读初值 → 错误①(0xFE) → 错误②(0xFD) → 错误③(0xFC) → 正确(0x00)

> 顺序较手册调整：正确分支（真实升级，6~7 分钟）只跑一次并放在最后，同时完成正确执行与错误后恢复两项验证（0xFC → 0x00），避免两次完整升级。

### 范围说明

- 正确分支只测一条（主 BMU 执行、给备 BMU 升级方向）；备 BMU 槽位错误分支（0xFB）不测；
- 正确分支是真实 FPGA 升级、耗时 6~7 分钟且期间主备均不响应其他操作，放在 11.3 组最后执行。

## 11.3-3 主备 SSD 相关遥测遥控 + 上下电控制

对应手册：2.1 / 2.2 / 2.3（备 BMU 不测）

### 测什么

0x9A05 的 SSD 上下电 4 条子命令执行后，慢遥中 SSD 量化值与状态位随子命令变化，验证两路独立控制及"单块低不报过低"的判定口径。

### 帧结构与测试数据

完整帧 = `9A 05` + 目标槽位（主 BMU `06`）+ 子命令 + 校验和。

| 子命令 | 完整帧 | 含义 |
|---|---|---|
| `0x77` | `9A 05 06 77 1C` | 全部下电 |
| `0x88` | `9A 05 06 88 2D` | 固件 SSD0 上电 / SSD1 下电（手册：SSD1 上电 / SSD2 下电） |
| `0x99` | `9A 05 06 99 3E` | 固件 SSD0 下电 / SSD1 上电（手册：SSD1 下电 / SSD2 上电） |
| `0xDD` | `9A 05 06 DD 82` | 全部上电 |

### 命名对照（重要）

固件/PL/遥测统一用 **SSD0/SSD1**（0-based）；手册用 **SSD1/SSD2**（1-based）。二者一一对应，别混：

| 手册叫法 | 固件叫法 | AD 通道 | 慢遥 data[4] | 电源状态位 data[5] | 上电命令 |
|---|---|---|---|---|---|
| SSD1 | **SSD0** | CH_1 | bits[5:4] | bit0 | `0x88` |
| SSD2 | **SSD1** | CH_2 | bits[7:6] | bit1 | `0x99` |

> 命名依据：慢遥变量 `u8VolSampl_SSD0_D0V9`（CH_1）/ `u8VolSampl_SSD1_D0V9`（CH_2）、PL 网名 `VCC_FT_SSD0_D3V3_EN` / `VCC_FT_SSD1_D3V3_EN`、PL 解码 0x11e（`0x88→2'b01`、`0x99→2'b10`，bit0=SSD0、bit1=SSD1）。代码注释里 `ycyk_get_vol_status` 把 CH_1 标为"SSD1"、CH_2 标为"SSD2"，是沿用手册叫法的历史遗留，与慢遥变量同路异名，勿混。

### 怎么判

1. 打印：每条指令后出现 `[CAN]: SSD Power Control (0xXX)`；
2. 遥测：循环发慢遥请求 `00 AA 51 FB`，读 slowFrame[27]（第 28 帧）data[2] 的 slot 标记，**等到标记 = 2 的那次上报**再取值：
   - slowFrame[25]（第 26 帧）data[4]：bits[7:6] = 固件 SSD1 量化、bits[5:4] = 固件 SSD0 量化（同字节低 4 位是其它电压，勿混）；
   - 量化值含义：`0x0 = 正常`、`0x1 = 过高`、`0x2 = 过低`；
   - slowFrame[25] data[5] bits[1:0] = SSD 电源状态位（PL 寄存器 0x11f 回读）：bit0 = 固件 SSD0、bit1 = 固件 SSD1。
3. 断言口径：

| 指令 | 量化断言（bits[5:4] / bits[7:6]） | 状态位参考（bits[1:0]） |
|---|---|---|
| `0xDD` | `0x0` / `0x0` | `11` |
| `0x77` | `0x2` / `0x2` | `00` |
| `0x88` | `0x0` / `0x2`（SSD0 正常、SSD1 过低） | `01` |
| `0x99` | `0x2` / `0x0`（与 0x88 互补） | `10` |
| `0xDD` 恢复 | `0x0` / `0x0` | `11` |

4. 状态位以量化断言为主判据；状态位按上表预期记录，若个别位序与预期不符但两轮一致，先记录再上报（PL 版本差异时以实际为准）；
5. 每条上下电指令后间隔 3~5 秒再读慢遥（等 AD 采样与电压稳定）。

### 顺带覆盖（手册 2.1）

凑到 slot=2 上报时，读数确认电压采样消息字段：`Msg_Id = 1051`（slowFrame[24] data[5..6]）、`Msg_Len = 17`（slowFrame[24] data[7] + slowFrame[25] data[0]）。

### 实现备注

- SSD 量化值在每次慢遥请求时由固件重新计算（AD 采样 + 阈值：SSD 路 >1000 判过高、<800 判过低）；
- 状态位由 PL 回读（0x11f）：bit0 = 固件 SSD0 电源、bit1 = 固件 SSD1 电源，BMU 仅采集转发；
- 用例结束必须发 `0xDD` 恢复全上电。

### 范围说明

- 只测主 BMU（目标槽位 `06`），备 BMU（`0E`）不测；
- 手册 2.3 的"上报正常/过低"为慢遥解析显示层口径，脚本按原始量化值断言，不硬判显示文字。

## 11.3-4 过流监测开关（0x9A1C）

对应手册：2.5（仅 2.5.1 / 2.5.2；2.5.3 断电保持不在自动化范围）

### 测什么

0x9A1C 开/关指令下发后，debug 串口出现对应同步打印，验证指令被接收并分别进入开、关分支。

### 帧结构与测试数据

完整帧 = `9A 1C` + 开关值(1) + 校验和(1)；校验和 = 全字节累加取低 8 位。

| 动作 | 完整帧 | 同步打印 |
|---|---|---|
| 开 | `9A 1C 55 0B` | `[CAN]: Current Monitor Open` |
| 关 | `9A 1C AA 60` | `[CAN]: Current Monitor Close` |

### 怎么判

- 顺序：关 → 开（结束保持在"开"，不把样机留在过流监测关闭状态）；
- 每条发送后对 debug 串口做关键字包含匹配，两条都命中即通过。

### 实现备注

- 处理函数 `ycyk_can_proc_current_ctrl`（RemCT_Can.c:1448），该指令无 ACK、无遥测位；
- 仅主 BMU 生效：备机 `g_u8CanFullDealFlag=1`，除加电配置外指令被直接吞掉、无任何打印（RemCT_Can.c:1589）；
- 每条指令会触发一次 PL MRAM 保存脉冲（0x320），用例各发一次、不循环。

### 限制

- 打印仅证明指令进入处理函数，不证明 PL 0x600 实际写入；
- 手册 2.5 所述"过流监测遥测位"在固件中不存在，不判；
- 断电保持归人工 2.5.3。

## 11.4-TOD TOD 解析（SC 422 口 GNRMC）

对应手册：3.1（只取 3.1.1 正确解析 + 3.1.2 中一种错误；3.1.3 / 3.1.4 不在自动化范围）

### 测什么

SC 422 口接收 GNRMC 语句，验证正确语句能解析并打印时间（秒数），错误语句有明确错误打印，且下一条正确语句可恢复。

### 前置条件

- debug 菜单按 `A` 切到 TOD 模式（默认是 SC 协议模式，不切不会有任何反应）；
- 按 `k` 打开 TOD 打印（否则无输出可判）；
- 用例结束按 `a` 恢复 SC 协议模式。

### 测试数据与判据

| 用例 | 发送 | 判据（包含匹配） |
|---|---|---|
| 正确 | 一条合法 GNRMC（时间/日期取当前值），以回车换行结尾 | 打印 `now time is <年月日> <时>:<分>:<秒> --`，随后打印 `<N>秒`，N 与注入时间按固件基准换算一致 |
| 错误 | 一条非 GNRMC 语句（如 `$GNGGA,...`），以回车换行结尾 | 打印 `NEMA语句错误：不是$GNRMC格式`；紧接着补发一条正确语句能正常解析出秒数（恢复验证） |

### 实现备注

- 语句以 `$` 开头、以 `\n` 结尾触发一次解析；

## 11.7-1 遥控指令复位流程（软复位 0x001A）

对应手册：3.3.1（3.3.2 防重复复位不自动化）

### 测什么

软复位指令下发后：先打印受理信息，约 60 秒后执行整板复位，随后系统重新启动、通信恢复。

### 帧结构与测试数据

完整帧 = `00 1A` + 校验和(1)，无参数：

```
00 1A 1A   （软复位）
```

该指令无 CAN 应答帧，全部判据走串口打印。

### 怎么判（打印包含匹配，按序）

1. 发送后出现 `[CAN]: Soft Reset 0x30c is`（受理，0x30c 计数自增）和 `RESET: Start:`；
2. 约 60 秒后出现 `RESET: Execute:`（等待窗口按 90 秒设置；若出现 `RESET: No Need:` 本次判异常，说明 60 秒内复位计数发生了变化）；
3. 随后出现上电 banner（`==================== BMU`）判定复位执行、系统重启；检测到重启后自动补发 `Z`（沿用 0.2 约定）；
4. 重启后发状态查询 `00 25 25`，收到 `00 2A 00 00 00 5A 5A chk` 判定通信恢复。

### 实现备注

- `RESET: Start` 与 `RESET: Execute` 之间约 60 秒只有这两条打印、没有其他输出，属正常等待；
- 该指令仅主 BMU 执行（备机 `g_u8CanFullDealFlag=1` 静默丢弃，无打印）；
- 用例会整板复位，放在本轮自动化尾部执行，前面用例的计数类观察项先完成。

### 限制

- 手册 3.3.2 防重复复位（No Need 分支）不自动化，留人工；
- 复位范围（是否连带备机/CPU）不在自动化断言内，只看主 BMU 重启。

## 11.7-2 BMU 电压低上报（快遥电压状态位）

对应手册：3.5（SSD 部分并入 11.3-3 流程；非 SSD 电压项环境受限）

### 测什么

SSD 上下电过程中，快遥电压状态位符合"单块低报正常、两块同时低报过低"。

### 怎么判

复用 11.3-3 的上下电序列，不新增激励；每条指令后（等 3~5 秒电压稳定）发快遥请求 `00 5A 5A`，取应答中 ID `0x13000045` 那帧的 data[1] bits[1:0]：

| 指令 | 预期电压状态 |
|---|---|
| `9A 05 06 DD 82`（全上电） | `0x2` 正常 |
| `9A 05 06 77 1C`（全下电） | `0x3` 过低 |
| `9A 05 06 88 2D`（SSD0 上电 / SSD1 下电，手册：SSD1/SSD2） | `0x2` 正常（核心：单块低不报过低） |
| `9A 05 06 99 3E`（SSD0 下电 / SSD1 上电，手册：SSD1/SSD2） | `0x2` 正常 |
| `9A 05 06 DD 82`（恢复全上电） | `0x2` 正常 |

状态编码：`0x1` = 过高、`0x2` = 正常、`0x3` = 过低。命名对照见 11.3-3。

### 实现备注

- 状态位在每次快遥请求时由 `ycyk_get_vol_status()` 重新计算：固件 SSD0/SSD1 任一 >1000 报过高；两块同时 <800 报过低；其它（含单块低）报正常；
- 与 11.3-3 的慢遥读数口径不同：慢遥每路 SSD 量化独立判定（<800 即 `0x2`），单块低时该路慢遥仍为 `0x2`；快遥整体状态位为 `0x2` 正常。两处读数一起采集，互为交叉验证；
- 快遥状态位只在快遥应答里，慢遥不重复携带。

### 限制

- 非 SSD 各路电压现场无法拉低，手册 3.5.1 的"数值与 3.00 轮一致"只做人工记录，不自动化；
- 仅主 BMU。

## 11.7-3 组播不计入正确指令计数

对应手册：3.4（用姿态组播验证，不用星历/04 消息，原因见实现备注）

### 测什么

姿态组播（0x0002）下发后，CAN 正确指令计数不变；普通单播指令后正确指令计数 +1。

### 测试数据

| 报文 | 发送内容 | CAN ID 特征 | 指令码 |
|---|---|---|---|
| 姿态组播 | 预置"姿态 ATTITUDE" | dst=0x3F、group=1（组播） | 0x0002 |
| 普通单播 | 自造 | dst=0x06、group=0（单播） | 0x9A14 |

普通单播完整帧（读主 BMU 电压，无副作用）：

```
9A 14 06 B4   （0x9A14，目标槽位 06）
```

### 怎么判

观测字段：发快遥请求 `00 5A 5A`，从应答（0x00A5）第 2 帧取 data[2] = CAN 请求计数、data[3] = 正确指令计数、data[4] = 错误指令计数（均为 8 位，按 mod 256 比较）。

1. 读快遥，记正确计数初值 N0；
2. 姿态组播连发 3 条；
3. 再读快遥：正确计数仍 = N0；请求计数比上一次读取多 4（3 条组播 + 本次快遥请求 1 次），证明组播确实被 BMU 收到；错误计数保持 0；
4. 发 1 条普通单播 `9A 14 06 B4`；
5. 再读快遥：正确计数 = N0 + 1，错误计数保持 0。

### 实现备注

- 组播帧（group≠0）落到默认处理分支时执行 `u8CanCorCnt--`（RemCT_Can.c:272），与校验通过时的 +1 抵消；遥测请求（快遥/慢遥/状态查询）也有对应回退，所以轮询快遥不改变正确计数；
- **为什么不用星历（0x0001）和 04 消息（0x0004）**：两者走 0x55 组播（dst=0x15、group=1），默认被 11.10 的过滤关闭（`g_u8Can55MulticastEnable=0`，可用 0x1F 开关打开），BMU 收不到，做不了计数探针。姿态组播走 0x7F（dst=0x3F、group=1），不受该过滤影响；
- 姿态组播为复帧消息，连发 3 条即 3 次消息处理（请求计数 +3）；
- 请求计数增量是"帧确实到达"的证据，防止"帧没收到导致计数不变"的假通过；错误计数若增长说明发送帧构造有误；
- 所有发送帧只走一个 CAN 通道（计数对 A/B 是全局的，双通道发送会重复计数）；
- 用例期间要求 CAN 总线无其他发送源，否则请求计数增量不可控。

### 限制

- 仅主 BMU：备机 `g_u8CanFullDealFlag=1` 时不进处理分支，所有收到帧都计入正确计数，规则与主机不同。

## 11.9 提日志遥控指令路由与日志主控

对应手册：5.2

### 测什么

| 用例 | 参数第 1 字节 | 参数第 2 字节 | 预期打印 |
|---|---|---|---|
| 指定槽位路由 | `0x11` | 指定槽位（如 `0x05`） | `CAN Log: Aim[0x11] Slot[0x5]` |
| 默认路由 | 非 `0x11`（如 `0x00`） | `0x05` | `CAN Log: Aim[0x0] Slot[0x5]` |

- 指令无 CAN 应答；打印回显的是参数本身，只能证明分支被走到，不能证明实际路由目标；

- 关闭状态下按 `z` 无输出属正常（OFF 打印在关闭生效前发出，仅当输出已开才可见）。

### 限制

- 实际日志生成与送达（CPU/OM 侧）不在断言内，只验证 BMU 侧分支与（可选）路由字节。

## 11.10 星历组播过滤（0x55 组播开关）

对应手册：5.3

### 测什么

0x55 组播（本星星历 0x0001、04 消息 0x0004 等，CAN ID 特征 group=1、dst=0x15）的开关：关闭时 BMU 收不到、开启后能收到、切换不影响普通单播。

### 前置假设

默认处于过滤（关闭）状态，用例直接从默认态开始。

### 测试数据

| 操作 | 帧 / 按键 | 打印 |
|---|---|---|
| CAN 开 | `9A 05 06 1F C4` | `[CAN]: 0x55 Multicast ON` |
| CAN 关 | `9A 05 06 F1 96` | `[CAN]: 0x55 Multicast OFF` |
| 菜单开 | debug 口按 `M` | `0x55 Multicast ON`（无 `[CAN]:` 前缀） |
| 菜单关 | debug 口按 `m` | `0x55 Multicast OFF`（无 `[CAN]:` 前缀） |
| 探测组播 | 预置"星敏感器 STAR"（0x0001，group=1、dst=0x15） | 无 ACK，以快遥请求计数观测 |

### 怎么判

观测：发快遥请求 `00 5A 5A`，取应答（0x00A5）第 2 帧 data[2] = 请求计数、data[3] = 正确计数。用"读一次快遥 → 发被测帧 → 再读快遥"的两次读数差值断言；快遥读取本身使请求计数 +1、正确计数不变。

1. 默认过滤态：读快遥 → 探测组播发 3 条 → 读快遥：请求计数只 +1（组播被过滤未收到），正确计数不变，错误计数 0；
2. 发 `9A 05 06 1F C4` 开：打印 `[CAN]: 0x55 Multicast ON`，伴随 `CANA INIT Success, 0x55 Multicast: ON`；
3. 开态：读快遥 → 探测组播发 3 条 → 读快遥：请求计数 +4（3 条组播 + 本次请求），正确计数不变（组播不计入），错误计数 0；
4. 单播不受影响：读快遥 → 发 `9A 14 06 B4` → 读快遥：请求计数 +2（单播 + 本次请求）、正确计数 +1；
5. 发 `9A 05 06 F1 96` 关闭：打印 `[CAN]: 0x55 Multicast OFF`；
6. 过滤恢复：读快遥 → 探测组播发 3 条 → 读快遥：请求计数只 +1，正确计数不变；
7. 开→关→开反复切换 3 次：每次 ON/OFF 打印都出现，期间单播查询始终有应答；
8. 菜单路径（可选）：按 `M` / `m` 各一次，出现对应打印，并用探测组播复核状态生效；
9. 结束保持关态。

### 实现备注

- 命中打印时注意区分路径：CAN 指令打印带 `[CAN]:` 前缀，菜单打印不带；
- 每次开/关组播都会重新初始化 CAN（短暂中断），切换前后不要有其他发送；
- 请求/正确计数均为 8 位模 256，按差值比较；快遥请求本身在响应构建前 +1，故每次读取都计入。

### 限制

- 仅主 BMU（槽位 `06`），备 BMU 的 0x9A05 不测；
- 组播内容本身不做业务校验，只验证"收到 / 收不到"。
