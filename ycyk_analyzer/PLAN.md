> 这份文档的目的：**换台电脑也能接着干**。所有结论都标注了"是实测验证过的"还是"待确认的"。

## 0. 一句话

把遥测 CSV（快遥 / 慢遥）解析成**中文字段名 + 判据着色**的 xlsx，替代并修正现有外部工具的错误解析。

---

## 1. 目标与范围（V1）

| 项 | 内容 |
|---|---|
| 输入 | 一个 CSV（快遥 或 慢遥） |
| 输出 | 一个 xlsx：sheet = `comman` + `slot0 / slot2 / slot3 / slot5` |
| 只做三块 | **快遥 T**（68 列）、**慢遥 T**（111 列）、**BMU**（1052 / 1051 / 1050） |
| sheet 内容 | `comman` = T 段（每包一行）；`slot*` = 只放该通道的 BMU（V1） |
| 时段 | **一行 = 一个时段**（不做时间窗口聚合） |
| 时间轴 | 第一行 = 0 s，按 CSV 行序推进；**不做丢包判据** |
| 阶段1 判据 | 只做**文字/枚举类**（中文枚举、状态位）；数字阈值留到阶段2 |
| 四态 | 通过 / 告警 / 异常 / 暂不判据（另：无填充 = 本帧该消息未出现） |
| 不做 | CAN 相关（`Can_Frame_Deal/`、`JiangCan_Tools/`、`NewCanWindow.py` 一律不碰）、Rust、单文件 exe、分组汇总 |

## 2. 已确认的决策（按时间顺序）

1. **不做合并表** —— 快遥出一张表、慢遥出一张表，各自输入各自输出。
2. **输出构型照抄外部工具产物**（`基带慢摇1_工具产物.xlsx` 的骨架），在其上只做两件事：**修正 BMU 归属/解析**、**加判据与着色**。允许删掉非 BMU 的其他 typeid 列。
3. **时段 = 一行**。
4. **丢包不判**，时间轴以 CSV 为准。
5. **快遥没有 slot**（只有 `comman` 一张 sheet）。
6. **通道1（slot2）本来就没有规划 BMU** → 该页 BMU 部分不建列。
7. **位序 = 高位先（MSB-first）** —— 已由实测证实（见 §3）。
8. **T 段定义沿用旧表**（`PreCanDeal` 的 标准快遥 / 标准慢遥51H）。
9. **新解析表（标三-慢遥测试表）基本不再改动**。
10. **代码结构可大刀阔斧，旧代码允许全部抛弃。**
11. **语言路线 = Python + PyQt（后续界面）**；Rust 搁置；交付形态"拷过去能跑即可"，不追求单文件 exe。
12. **本次不碰 CAN 老代码**（但它有 bug、也是 T+Z 结构，将来要改；本项目的内核设计已为它预留复用）。

## 3. 数据事实（**全部为实测验证结果**，不是推测）

### 3.1 CSV 结构

- `基带慢摇1.csv`：**271 列 / 64 行**，UTF-8 无 BOM、LF 换行、无引号、无空字段（每行恰好 270 个逗号）。
  列布局 = `DMTime, SatTime` + **111 个 `TMXZJDT2xxx`** + **148 个 `TMXZJDZ2xxx`** + 10 个元数据列（`apid/backFlag/channelCount/channelId/oddEvenFlag/pklen/pknum/secretFlag/seiflag/ver`）。
- `基带快摇.csv`：**80 列 / 65 行** = `DMTime, SatTime` + **68 个 `TMXZJDT1xxx`** + 10 个元数据列；**无 Z 段**。

> ⚠️ 教训：**不要用 WPS / Excel 的肉眼核对列。** 该文件是 UTF-8 无 BOM + 81 列中文，Excel 按 GBK 打开会乱码；271 列滚到 JA~JK 双字母区极易点错列（曾把 `channelId`(JE=5) 误看成 `TMXZJDZ2148`(JA=0/1/2/3)）。核对列用"名称框输入地址"，或直接读字节。

### 3.2 一行 = 一个 slot 包；Z 段载荷 = 148 字节

- `TMXZJDZ2148` = **帧序号 / 通道号**（取值 0/1/2/3 → slot0 / slot2 / slot3 / slot5）。
- 载荷 = `Z2001 ~ Z2148` = **148 字节**，末尾 1 字节即帧序号。
- **帧内消息位置不固定**，表只是"字典"，必须走游标解析。

各通道实测布局（字节偏移）：

| 通道 | 实测消息序列 |
|---|---|
| 0（slot0） | `1000`@0(25B) → `1800`@25(28B) → `1100`@53(44B) → `1101`@97(25B) → `1052`@123(24B) → 帧序号@147 |
| 1（slot2） | `1010`@0(10B) → `1705`@10(32B) → 空槽 |
| 2（slot3） | 空槽 0~125 → **`1051`@126(21B)** → 帧序号@147 |
| 3（slot5） | `1700`@0(109B) → `1050`@109(38B) → 帧序号@147 |

### 3.3 位序 = 高位先（MSB-first）

用 `1101`/`1000` 等块的字段与外部工具产物逐格比对：**(高位先命中, 低位先命中) = {(T,T):1154, (T,F):398, (F,T):0}** → **高位先 1552/1552 全命中**。这次比对同时验证了消息定位、字段位宽、取值三段链路。

### 3.4 BMU 段按**帧尾固定位置**解析

表内两处备注明确写着：**「注意：BMU上报遥测按固定位置解析」**（通道0 行86「预留」、通道2 行90「保留」）。
→ 解析策略：**BMU 按帧尾锚定；其余消息走游标 + 跳空槽 + 未知 ID 报错。**

### 3.5 表自带位长自检：1184 bit

新表每个 slot 页的消息位长合计 = **1184 bit = 148 字节**，与线上载荷完全一致：

| 通道 | 消息位长构成 | 合计 |
|---|---|---|
| 0 | 1000(200) + 1100(352) + 1101(200) + 1800(232) + 1052(200) | 1184 ✅ |
| 2 | 1010(80) + 1200(296) + 1502(280) + 1705(352) + 1051(176) | 1184 ✅ |
| 3 | 1700(872=109B) + 1050(312) | 1184 ✅ |
| 1 | 1010(80) + 1200(296) + 1502(280) + 1705(528) | 1184 ✅ |

页末还有一行「无名、位长 = 1184」的校验行（**解析时跳过，但可用作自检**）。

### 3.6 T 段不需要位域解码

CSV 里 T 段**已经是解码后的中文枚举或数值**（慢遥1：**81 列中文枚举** + 178 列数字；快遥以枚举为主）。
→ T 段只需「列 ↔ 中文名」的**行序映射**（已验证：偏移 k=0 是唯一零冲突解；111 列 ↔ 51H 表 1:1 严丝合缝，68 列 ↔ 快遥表 1:1）。

### 3.7 采样与时序

- 两条流都是 **8 s / 包**（快遥中位 8.01 s、慢遥 8.02 s；区间 3.9~25.1 s）。
- 慢遥包按 slot 轮转 → **同一 slot 每 4 行一次 = 32 s**。
- 存在丢包（慢遥 `pknum` 缺 4 个号；快遥步长 1/2/4/6）。**V1 不判丢包。**

### 3.8 外部工具的解析质量（用作回归基准）

外部工具（`自主管理综电模拟工具_0910.exe`）产物：`slot0(231列/31行)`、`slot2(213/17)`、`slot3(243/**0**)`、`slot5(269/16)`、`其他数据(271/0)`。

- ✅ **通道0 / 通道1 / 通道3 正确**（可当黄金标准）。
- ❌ **通道2 的 15 行被错归进 slot0**，并用 slot0 的 `1052`（电流，8bit）去解 `1051`（电压状态，2bit）的字节 → **23% 的行数值不可用**。
  - 证据：那 15 行的 `消息ID（type=1000/1100/1101/1800）` 全空；`消息ID（type=1052）` 读到 **0** 仍照填；`PLP1系统…电流` = 240（= 原始 byte 144）、`BMU系统的电流` = 255（= byte 146）——而那些字节属于 1051 的载荷区。
  - 成因推断：工具似以"帧首消息 ID"判通道；通道2 这帧前 126 字节全 0 → 判不出 → 退回第一张表 slot0。

## 5. 解析表结构（`标三-慢遥测试表-20260512.xlsx`）

sheet：`修改记录`（14 条变更）+ `通道0（slot0）`109行 / `通道1（slot2）`91行 / `通道2（slot3）`121行 / `通道3（slot5）`147行。
（行数含表头与页末校验行。窗口命名为 `通道N（slotM）`，其中 N=0~3 对应帧序号，M=0/2/3/5。）

**18 列**（列序即索引，解析靠索引不靠表头文字）：

| # | 列名 | 说明 |
|---|---|---|
| 1 | 模块 | 归属模块（OM / PLP0 / BMU固定填写 …） |
| 2 | 序号 | 页内序号 |
| 3 | 遥测代号 | **全空** → 列名映射只能靠行序 |
| 4 | **参数名称** | 中文字段名（消息切分靠它：含"消息ID"即新消息开始） |
| 5 | 数据类型 | 无符号数 … |
| 6 | 转换公式 | 全为 `/`（规则实际写在"备注"） |
| 7 | 转换后数据类型 | 整数 … |
| 8 | **上限** | **列在，100% 空** |
| 9 | **下限** | **列在，100% 空** |
| 10 | 期望值/预设值 | 空 |
| 11 | **单位** | **列在，100% 空** |
| 12 | **长度/bit** | 位宽（累加得字段偏移） |
| 13 | **备注** | 86% 有值；**解码/枚举规则实际在这里**（如 `BitMap类型，0表示正常。Bit0：没工作起来`、`0:6槽位BMU；1:14槽位BMU`、`1：枚举完成,0：枚举中`） |
| 14~16 | 测试时间 / 研发支持 / 验证结果 | 质量追踪，V1 不用 |
| 17~18 | 总包长 / 2368 | 表头常量（2368 = 2 × 1184 = T段 + Z段，已确认口径） |

**消息切分规则**：从"参数名称"含 **`消息ID`** 的行开始为一条新消息；`备注` 里的 `type=xxxx` 给出类型号（1050/1051/1052/1000/1010/1100/1101/1200/1502/1700/1705/1800），`length=NN字节` 给出载荷长度（**不含 4 字节消息头**）。

## 6. 代码结构（待建，允许抛弃旧代码）

```
ycyk_analyzer/
  spec.py        # 读 18 列表 → PacketSpec / SlotSpec / MessageSpec / FieldSpec
                 #   含：消息切分、位宽累加、页末 1184 校验、备注规则提取
  table_csv.py   # CSV 读取：显式 UTF-8、按索引取列、行列数校验
  frame.py       # 帧切分：T段→中文名映射；Z段→字节流
                 #   BMU 按帧尾锚定；其余消息走游标 + 跳空槽 + 未知ID报错
  bitfield.py    # 位域解码（MSB 先）+ 越界保护（越界抛错，不静默填数）
  values.py      # 值对象：Raw / Enum / Numeric（判据输入统一）
  rules.py       # 判据引擎：阶段1 = 枚举白名单；阈值/趋势接口预留
  rules.csv      # 可配规则（白名单 / 忽略 / 阈值）—— 用户可改
  report.py      # 出 xlsx：多 sheet、四态着色、字段总判断行、异常清单
  cli.py         # 入口
  spec/          # 版本化的解析表（已就位）
tests/
  fixtures/ycyk_0914/   # 回归样本（已就位）
```

设计要点：
- **解码内核是纯函数**（只吃 `bytes` + 字段表，只吐 `{字段: 值}`）→ CAN / CSV / 实时流共用，将来换语言也只重写这一层。
- **规则表与四态模型在阶段1 就建好**，阶段2 加阈值时不返工。
- 输出层的 xlsx 依赖 `openpyxl`；打包走 PyInstaller **onedir**（不受工程里 cp38 的 `can_core` 限制，本包不依赖它）。

## 7. 回归策略

1. **黄金标准对拍**：用 `基带慢摇1_工具产物.xlsx` 与自研解析结果**逐格比对**（通道0/1/3 应完全一致；通道2 应"我们正确、工具错"）。此法是本项目已验证有效的手段。
2. **表自检**：每 slot 页位长合计必须 = 1184 bit，否则加载即报错。
3. **边界用例**：空槽、未知消息 ID、字段跨消息边界、少 1 字节（已知 `1101` 多 1 字节 / `1051` 少 1 字节的历史现象）。
